# 已知限制（v0.1）

**这一页描述的是假阴性：工具说「无结构差异」，而网表其实不等价。**
比误报危险，因为用户会当真。修完之前，`rc=0` 不能当等价证明。

## 1. `.param` 表达式不求值

```spice
.param rr=1k
R1 in n1 rr        * 器件值引用参数名
```

只把 `.param rr=1k` 改成 `2k`，器件行一个字不动：v0.1 **报「无结构差异」，rc=0**。
原因：参数位置只做字符串比较，`rr` 与 `rr` 相等。

**规避**：先展开参数再比较，或另外检查 `.param` 块本身的 diff。
**计划**：v0.2 求值，或至少把 `.param` 块变更列为 `uncertain`（rc=2）。

## 2. `.include` 不展开

```spice
.include sub1.sp
```

`.include` / `.inc` 行整行略过，被包含文件的内容不参与比对。
两个网表分别 include `sub1.sp` 与 `sub2.sp`，内容不同 → v0.1 **报 rc=0**；include 指向不存在的文件也 rc=0。

**规避**：调用方先把 include 展开成单一网表，再喂给工具。
**计划**：v0.2 内置展开（相对路径、深度上限、循环检测）。

## 3. 分析语句不参与比对

`.tran` / `.ac` / `.dc` / `.ic` / `.meas` 等改动不检出。

**理由**：v0.1 只做结构（拓扑 + 器件参数 + 模型），分析设置属于另一层。
**计划**：v0.2 起把分析语句变更单独列为 `uncertain`，由使用者决定是否在意。

## 4. 其他边界

- 器件子集仅 `R C L D M Q X V I`，其余类型整行忽略（不报错）。
- 不支持参数化子电路（`subckt` 形参求值）、不支持波形 / 测量语句的语义比较。
- 规模：已实测到 **2 万只器件**（R/C/L 混合、3 万个节点，0.43 秒，单核），
  只报出预埋的 2 处改动、零误报。更大规模与 `.subckt` 深度嵌套未压测。
- 方言：按 ngspice 风格 SPICE3 子集实现；Spectre / HSPICE 特有语法未覆盖。

## 5. 规模实测

| 器件数 | 耗时 | 结果 |
|---|---|---|
| 1,000 | 0.17 s | rc=1，报出预埋 2 处改动，零误报 |
| 5,000 | 0.21 s | 同上 |
| 10,000 | 0.33 s | 同上 |
| 20,000 | 0.43 s | 同上 |

环境：Windows / CPython 3.14，单核，无 JIT。样例为扁平网表（无 `.subckt`），节点数约为器件数的 1.5 倍。
**仍是自造网表**，不是真实产线数据。

## 5. 方言覆盖：147 份 ngspice 官方示例实测

修掉三处方言问题后（首行标题、`.control` 块、数字节点名），按文件与自身比对的结果：

| 结果 | 份数 | 占比 |
|---|---|---|
| rc=0 干净 | 131 | 89.1% |
| rc=3 解析失败 | 14 | 9.5% |
| rc=1 误报 | 2 | 1.4% |

- 读不了的主因：`F`/`G` 受控源 `POLY(...)` 写法（7 份）、`PWL` 参数续行（2 份）、非标准器件名（2 份）、嵌套 `.subckt`（1 份）。
- 那 2 份误报是**同一 refdes 多实例**（`xrcv` 出现两次、指向不同子电路）导致配对退化，属已知缺陷，优先修。
- **不要写「支持 SPICE 网表」**：按 ngspice SPICE3 子集实现，约 11% 的真实网表读不了。详见 [real-netlist-report.md](real-netlist-report.md)。

## 这些限制怎么被钉住的

`tests/blackbox/test_edges.py` 里，第 1、2 条写成 `unittest.expectedFailure`：
现在它们「按预期失败」，**修好后会变成 unexpected success，提醒维护者删掉装饰器、改成正常断言**。
证据不删，红灯不藏。

# 设计说明

## 为什么不用普通 diff

网表里同一份电路可以有无数种写法：

- 器件顺序不同；
- refdes 编号不同（`R1` 改叫 `R7`）；
- 内部节点名不同（`n1` 改叫 `net_a`）；
- 数值写法不同（`4k7` / `4700` / `4.7e3`）；
- 续行与注释位置不同。

文本 diff 会把它们全部报成改动，真正要紧的那一处（比如 `R2 2k → 3k`）淹在噪声里。
spice-diff 先把每个器件归约成签名，再比签名。

## 签名的构成

```
signature = (device_kind, sorted(param_names), canonical_net_tuple)
```

- 节点按拓扑位置规范化：`0` 是全局地，永不重命名；`.global` 声明的网络身份固定；其余按连接关系规范化，不按出现顺序编号。
- 参数名大小写不敏感，值先做数值归一（`4k7`、`4.7k`、`4.7e3`、`4700` 归一到同一浮点数）。
- `.model` 单独比，只比双方都出现的参数；缺失视为取默认值。
- 顶层未被 `.global` 声明的网络改名，不计为改动；要「改名也算改动」必须先 `.global` 声明。

## 配对

1. 按签名分组，组内一对一时直接配对。
2. 组内多对多（同型同连接、只差 refdes）时无法唯一确定身份 → 输出 `uncertain` + 候选，退出码 2。
3. 数量可定、身份不可定（同签名并联由 2 只降为 1 只）：报 `device_removed`，但 `refdes` 填 `null`。

**宁可不判，也不猜。** 猜错一个 refdes，审阅的人会去看错地方，比不报更贵。

## 确定性

- 输出不依赖字典顺序（显式排序）、不含时间戳、不含绝对路径（只输出文件名）。
- stdout 固定 UTF-8 + LF，不跟随本机 locale（Windows 上尤其重要：GBK locale 会把中文报告写崩）。
- 同一对输入两次运行，字节级一致——这是 CI 能直接断言退出码的前提。

## 为什么不展平层次

展平后 `buf/R1` 和 `amp/R1` 会撞名，报告里只剩一堆 `R1`。
保留 `.subckt` 层次后，差异直接标在 `buf` 里，改哪里一目了然；代价是不能跨层做等价化简，v0.1 接受这个代价。

## 错误处理

解析错误抛 `ParseError(fname, line, ref, msg)`，由 CLI 统一转成 stderr 一行 + 退出码 3。
**不做「尽力而为」的容错解析**：猜出来的结构拿去做 diff，比直接报错危险得多。

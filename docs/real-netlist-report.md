# 真实网表实测报告（2026-11-21）

**一句话：v0.1 拿到 147 份第三方真实网表上跑，修三个方言问题之前 83% 直接解析失败；修完 89% 能干净自比对。**

## 方法与口径

- 语料：ngspice 官方仓库 `examples/` 全树里的 `.cir` / `.sp` / `.net`（GitHub API 枚举 230 个，取小于 300 KB 的，实际下载到 **147 份**）。
- 判据：每份文件**与自身比对**。同一条输入自己跟自己比，正确结果只能是 `rc=0`、零差异。
  - `rc=3` = 解析器读不了这份网表（方言不支持）；
  - `rc=1` = **误报**（两份完全相同的网表报出差异），这是最严重的一类。
- 环境：Windows / CPython 3.9，工具取 `src/spice_diff`，`PYTHONPATH` 指它。

## 修之前：18 份抽样，15 份读不了

| 结果 | 份数 |
|---|---|
| rc=3 解析失败 | 15 |
| rc=0 正常 | 3 |

**83% 的真实网表读不进来。** 全是方言问题，不是电路问题：

| 报错 | 真实网表里的原样 |
|---|---|
| `<Inverter> 节点数不足` | 第 1 行是标题 `Inverter example circuit`，被当成了 `I` 型器件 |
| `<Colpitt's> 节点数不足` | 第 1 行标题 `Colpitt's oscillator` |
| `<set> 节点数不足` / `<dowhile>` / `<run>` / `<meas>` | `.control` … `.endc` 里的解释器脚本被当成网表语句 |
| `<XU200> 节点名不合法: 0` | `XU200 0 11 10 9 VU2bias+ OP177A` —— 数字节点名被判定非法 |

## 修了什么（三处，都在 `parse.py`）

1. **首行标题**：SPICE 约定第 1 行是标题。实现上只在「该行解析不成器件」时才跳过——
   不少提取工具导出的网表没有标题、首行就是器件，一刀切会静默吞掉一只器件（假阴性），所以按解析结果判。
2. **`.control` … `.endc`**：块内整段跳过。里面是 `set` / `run` / `meas` / `dowhile` 之类的解释器脚本。
3. **数字节点名合法化**：`X` 实例不再拒绝 `0 1 2 3` 这类节点名。这类拒绝本来是为了防「尾部裸数字是参数」，
   但尾部 `key=value` 已由 `_split_params` 收走，剩下的都该当节点。

三条都补了回归测试（`tests/blackbox/test_edges.py::TestRealNetlistDialect`）。
**验证方式**：把 `SPDIFF_SRC` 指回仓库原版 `src/`，这三条测试全红；指回修好的版本，全绿。

## 修之后：147 份真实网表

| 结果 | 份数 | 占比 |
|---|---|---|
| rc=0 干净自比对 | **133** | **90.5%** |
| rc=3 解析失败（方言不支持） | 14 | 9.5% |
| rc=1 误报 | **0** | **0%** |

第一轮修方言后是 `131 / 14 / 2`；第二轮修掉配对缺陷后误报清零，见下节。

### 剩下 14 份 rc=3 的归类

| 原因 | 份数 | 说明 |
|---|---|---|
| `F`/`G` 受控源 `POLY(...)` 写法 | 7 | `f1 1 0 poly(2) v1 v2 0 1` 这类多控制节点语法，v0.1 只认 4 节点短写法 |
| 电压源 `PWL`/续行参数 | 2 | 值部分被拆成多个 token |
| 忆阻器 `Rmem` 自定义模型行 | 2 | 非标准器件名 |
| 嵌套 `.subckt` | 1 | 明确不支持（会主动报错，不静默展平） |
| 其他短写 | 2 | 节点数不足的不同变体 |

### 第二轮：那 2 份 rc=1 的根因与修法（真缺陷，不是方言）

`examples/TransmissionLines/ltra5_1_line.sp` 与 `txl4_1_line.sp` 里，**同一个 refdes `xrcv` 出现两次**，
分别实例化不同子电路（`bjtdrvr` / `dioload`）。同 refdes 多实例时，配对退化成
「一条 `device_added` + 一条 `device_removed`」，于是**自己跟自己比也报 4 行差异**。

- 严重性：这是**误报**，优先于任何新功能。
- 实际修法（`core.py::_diff_scope` 开头新增第 0 步）：**先把字面完全相同的实例一对一配掉**
  （键 = `refdes + 类型 + 子电路/模型名 + 节点序列 + 参数`），配剩下的才按 refdes、再按签名配。
  这类文件自然归零，且不影响真改动——新增测试里有一条专门盯「同 refdes 文件改一个电阻值仍必须报出来」。
- 效果：147 份自比对从 `131/14/2` 变成 **`133/14/0`**，误报清零。

## 顺带修掉的一处措辞（假等价）

`rc=0` 时原来输出「退出码 0（**两份网表结构等价**）」。这正是发布页反复强调不许出现的那句话。
已改成：

```
退出码 0（未发现结构差异；这不等于两份网表等价，见 docs/limitations.md）
```

## 结论

- v0.1 的三条已知假阴性（`.param` / `.include` / 分析语句）与这批方言问题**不重叠**，是两回事。
- 方言修复把真实网表可用率从 **17%** 提到 **90.5%**（133/147），误报从 2 份降到 0 份；两处改动分别只动 `parse.py` 三小段、`core.py` 一个配对步骤。
- **仍有 11% 真实网表读不了**，发布页必须写清「按 ngspice SPICE3 子集实现」，不能写「支持 SPICE 网表」。
